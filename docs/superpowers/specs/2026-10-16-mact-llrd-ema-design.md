# MACT 分层学习率与 EMA 四组对照设计

日期：2026-10-16。状态：用户已认可四组对照方向；本文补充的具体设计待审阅。

## 目标与范围

用户优先考虑稳定提高指标，接受成熟方法。本轮目标是验证分层学习率（LLRD）和指数移动平均权重（EMA）能否改善 MACT 的泛化，并区分各自及组合的效果。部署仍为单模型。方案不预设一定涨点。

继续使用共享的 `mact` 源码，通过配置区分实验；保留 `configs/base.json`、历史权重、结果和官方数据文件。基础版本为当前提交 `8c75ee7`，模型为 DeBERTa-v3-base、冻结 SigLIP2 缓存、fusion、五标签约束 CRF。本轮不开启 R-Drop、OCR、辅助情感损失、视觉门控、词间注意力或部分冻结，不修改模型前向和标签定义。

本轮只读取 Train/Dev 的样本和视觉缓存。Test 路径可保留在已有配置元数据中，但不读取、散列或评估 Test 数据、Test 缓存和 Test 预测。后续 Test 评估及额外种子复核另行列出，不包含在本轮自动调度中。

## 依据与不确定性

- 现有 seed42 Twitter2017 Dev 的 MATE F1 为 92.65%，边界匹配后情感准确率为 72.69%，说明情感判别存在明显改进空间。
- 训练末期损失很低，但 Dev 最优与末轮仍有差距；这是采用温和微调、权重平均的动机，不足以证明具体根因。
- 已有冻结底部六层的 seed42 实验，在 Twitter2015/2017 的 Dev Joint F1 分别下降约 2.27/0.68 个百分点。因此本轮保留全部文本层可训练，只降低底层更新幅度。
- 既有 R-Drop 收益随数据集和种子组变化，不直接加入本轮组合。
- 上一轮对已有 Dev 预测的探索性分析发现实体情感先验相关误差；本轮将其作为辅助诊断，不增加去偏目标，也不把相关性解释为因果。

文献依据：

- [ULMFiT, ACL 2018](https://aclanthology.org/P18-1031/)：不同层采用不同学习率的微调思路。迁移到当前 DeBERTa 是本轮待验证的工程选择。
- [Exponential Moving Average of Weights in Deep Learning: Dynamics and Benefits](https://arxiv.org/abs/2411.18704)：EMA 的训练动态和泛化研究。论文结果不构成 MACT 收益保证。
- [DPCI, EMNLP 2025](https://aclanthology.org/2025.emnlp-main.1158/)：方面身份与情感先验偏差的相关研究；其给定方面分类设置不同于本项目联合抽取。

## 四组结果与十二条训练轨迹

固定数据集 `twitter2015/twitter2017`，共同种子 `42/43/44`，每条轨迹 35 epochs。

| 训练轨迹 | 普通权重结果 | EMA 权重结果 |
|---|---|---|
| uniform：原学习率分组 | A：原 MACT 对照 | B：MACT + EMA |
| llrd：分层学习率 | C：MACT + LLRD | D：MACT + LLRD + EMA |

两类轨迹 × 两套数据 × 三种子 = **12 次训练**，产生 **24 个独立选模结果**。EMA 不参与反向传播或优化器更新，因此同一轨迹的普通/EMA 权重共享完全相同的训练样本和更新过程。

每条轨迹均每 epoch 评估普通和 EMA 权重，各自以 Dev Joint F1 最大值独立选模，并列取最早 epoch。每组均有 35 次候选评估，不将两个权重流混成 70 次候选后择优。历史 baseline 只作参照，配对主对照使用本轮 uniform 普通权重结果。

## 分层学习率规则

新增 `layer_lr_decay`，默认 `1.0`；本轮 llrd 固定 `0.9`，不扫描其他值。校验为有限数且 `0 < value <= 1`。

对 DeBERTa 的 N=12 个文本层，层号 i=0..11 从底到顶：

`lr(layer_i) = 2e-5 * 0.9 ** (11-i)`

- 顶层：`2e-5`；最底层：约 `6.2762e-6`。
- 输入 embeddings：`2e-5 * 0.9 ** 12`，约 `5.6486e-6`。
- 共享 `encoder.rel_embeddings` 和 `encoder.LayerNorm` 使用 embeddings 学习率；若存在 `encoder.conv`，使用最底层学习率。
- 非文本参数，包括投影、注意力、视觉输出头、文本头和 CRF，均保持 `1e-4`。
- weight decay 沿用现有实现：二维及以上参数为 `0.01`，其他参数为零。维持既有 AdamW、10% warmup、线性衰减和梯度裁剪。
- 每个可训练参数必须且只能进入一个优化器分组。启用 LLRD 时出现未识别的文本参数应报错，禁止静默采用猜测学习率。
- `layer_lr_decay=1.0` 必须沿用原优化器分组与参数顺序，避免无意改变基础训练行为。

启动记录每个分组的参数名称、数量、基础学习率和 weight decay。全部文本参数保持可训练。

## EMA 规则与隔离

新增 `ema_decay`，默认 `0.0` 表示关闭；启用时要求有限数且 `0 < value < 1`。本轮两类轨迹均固定 `0.99`，不扫描其他值。

模型初始化完成后复制浮点参数作为 EMA 初值。每次成功 `optimizer.step()` 后更新一次：

`theta_ema = 0.99 * theta_ema + 0.01 * theta_online`

从第一次实际优化器更新开始，包括 warmup；不按 micro-batch 更新，不使用偏差校正或额外预热。记录 EMA 更新次数并要求等于优化器更新次数。EMA 使用 FP32、无梯度，包含 CRF 可学习起止/转移参数。固定约束掩码等 buffer 不参与平均，评估时与在线模型保持一致；SigLIP2 使用已有冻结缓存，不新增视觉模型副本。

EMA 评估临时切换参数内容，不能替换被优化器引用的 Parameter 对象。使用异常安全的恢复逻辑，评估结束或失败后均恢复在线参数、buffer 和各子模块 train/eval 标志。EMA 评估以及其 DataLoader 迭代前后保存并恢复 Python、NumPy、PyTorch CPU 和实际使用 CUDA 设备的 RNG 状态，防止额外评估改变下一轮训练。

EMA 关闭时不创建影子参数、不额外评估、不改变 RNG。启用 EMA 时在线参数的优化器轨迹必须与相同配置下 EMA 关闭的轨迹一致（CPU 确定性测试严格验证）。GPU 的普通数值非确定性另行如实记录，不承诺历史训练逐位复现。

训练的额外成本为影子权重存储、逐步平均和每 epoch 一次额外 Dev 前向；部署加载选出的单份权重，推理结构与原 MACT 相同。

## 代码接口与结果文件

预期改动范围：

- `src/mact/finetuning.py`：明确的 LLRD 参数分组；原冻结函数保留。
- `src/mact/averaging.py`：独立 EMA 状态、更新和异常安全评估上下文。
- `src/mact/train.py` / `runtime.py`：配置校验、优化器分组、每次更新后的 EMA 调用及两个权重流的评估选模。
- `src/mact/experiment.py`：普通和 EMA 最优 checkpoint 的完整 Dev 重载核对。
- `configs/`：两份独立实验配置，除 `layer_lr_decay` 外完全相同，均开启 EMA；`base.json` 不修改。
- `scripts/`：本轮 Dev-only 调度与严格配对汇总，复用已有调度组件，不复制训练源码。

普通权重保留原文件约定：`best.pt`、`last.pt`、`best_dev_predictions.json`、`summary.json`。EMA 结果放在同一轨迹的 `ema/` 下，使用相同文件名及独立重载报告。`history.json` 每个 epoch 同时记录两组 Dev 指标及 EMA 更新数；`summary.json` 的原字段保持表示普通权重，新增 EMA 引用字段，避免旧工具误读。

EMA checkpoint 保留既有模型权重格式，并增加描述性元数据（权重来源、decay、更新数、选中 epoch、轨迹身份）。所有新增字段须保持旧权重可加载。它是可直接推理的独立 checkpoint，不依赖在线权重；本轮不新增 optimizer/RNG 断点续训能力。

汇总键为 `(dataset, seed, trajectory, weight_source)`，拒绝重复、不明或缺失成员。完整后输出 A/B/C/D 的均值、样本标准差、相对 A 的逐种子差值、差值均值/标准差及胜/平/负。缺失时仅报告状态和单项结果，不将部分种子统计标成完整结果。

## 运行与日志

沿用 `.runtime/bin/python` 和本地资源。实现前保留共享源码目录；不为每组实验复制源码。

GPU0 默认串行执行 Twitter2015 的六条轨迹，GPU1 串行执行 Twitter2017 的六条轨迹；每卡最多一个本轮训练任务。先检查设备及已有任务，若 GPU 不适合启动则明确报告，不能终止其他任务或退回 CPU。普通及 EMA 评估共用该任务设备。

正式运行前固定源码、配置及 Train/Dev 资源身份；队列启动下一项前核对。输出目录使用全新名称，不覆盖任何已有输出。采用可脱离交互终端的后台调度，保存 PID、日志、任务状态及错误。记录实际启动与首轮训练证据后才能报告训练已经开始。

专用调度必须显式 `--train-only`；现有 `run_seeds.py` 默认 Test 行为不直接用于本轮。日志按 epoch 汇总，分别标记 `DEV ONLINE` 与 `DEV EMA`，不打印逐 step 日志。

## 验证要求

1. LLRD 参数分组全覆盖、无重复、逐层数值正确，共享参数策略明确；默认值还原原分组和更新。
2. EMA 公式、初始化、实际更新次数和梯度累积行为正确；非有限配置被拒绝；影子权重不接受梯度。
3. EMA 参数切换后的正常恢复、异常恢复、buffer/模式恢复；优化器参数对象身份不变。
4. 至少跨两个训练 epoch 的 CPU 确定性对照：开启 EMA 额外评估与关闭 EMA 时，在线损失、参数、优化器状态及后续 RNG 一致。这覆盖 DataLoader 消耗 RNG 的隐患。
5. 普通和 EMA 独立最优 epoch、并列规则、保存与加载正确；重载后的完整 Dev 指标和逐条预测一致。
6. 调度命令明确 Dev-only，覆盖 Test 数据/缓存读取保护、失败及不完整汇总、源码变更检测。
7. 完成相关单元测试和项目全套回归；随后两种轨迹各两套数据的真实本地骨干 CUDA 短训练 smoke，验证梯度、EMA、保存重载、显存与资源路径。smoke 不计入正式指标。
8. 新功能关闭时通过基线兼容验证；所有测试和 smoke 通过后才启动正式十二条轨迹。

## 结果判定

主指标为 Dev Joint F1，同时报告 MATE 和边界匹配后的情感准确率。比较不同模型情感改善时，增加双方都匹配正确的共同边界子集，避免边界集合变化造成误读。可附已有方面先验分组诊断，分组规则固定为 Train 中名称 casefold 后精确匹配、至少三次出现、唯一多数情感；不据此调参或选 checkpoint。

候选进入后续复核的规则：两个数据集相对本轮 A 的平均 Dev Joint F1 均严格为正，并且每个数据集至少两个种子严格提升。否则保留结果，但不将其称为稳定增强。若多个候选满足，按两个数据集等权平均的配对增益选择，完全并列时优先 B、再 C、再 D。该规则仅是探索性筛选，不是统计显著性声明。

三种子结果不能独立证明稳定泛化。完成本轮后提交完整对照报告，再安排预先固定额外种子的复核与最终 Test 评估；不自动扩大训练或按 Test 选种子。若没有方案通过筛选，明确报告无可靠提升，不自动叠加其他模块。
